# Database and migrations

PostgreSQL, reached through `database/sql`. Migrations live in `database/migrations/` and
are applied by `make migrate-up`.

## Migrations

- Treat the deployed first-application behavior of an applied `up` migration as
  immutable; repair schema or data with a new forward migration. Editing comments, fixing
  a broken `down`, or making an `up` safe to replay after its matching `down` is allowed
  when the initial outcome and already-upgraded databases do not change. Record the reason
  in the change.
- Every migration has a matching `down`, and `make migrate-down-all` is run in CI so the
  rollback chain stays executable. A destructive or security-sensitive data change may
  use a documented no-op `down` when reversal would be less safe than leaving the new
  state in place. Phase 1 laid the
  whole schema down first, so a table or column may exist ahead of any code that reads it
  (`password_reset_tokens`, `game_rounds`, the session metadata columns); from here on a
  migration ships in the same change as the code that depends on it.
- Name them `NNNNNN_verb_object.up.sql` / `.down.sql` with monotonically increasing
  numbers. Never remove a version that a database may already record; retain a documented
  no-op bridge pair when a legacy version has no remaining schema action.

## Column rules

- Money is `BIGINT` minor units plus a currency column. Never `NUMERIC`, `FLOAT`, `REAL`,
  or `DOUBLE PRECISION` for authoritative money.
- Timestamps are `TIMESTAMPTZ`, stored UTC. Never `TIMESTAMP` without a time zone.
- Externally visible identifiers are UUIDs, non-sequential, generated by the database. A
  `BIGSERIAL` may exist as an internal key but is never exposed in an API.
- Index foreign keys and list filters when the expected data size and query plan justify
  it. Composite and partial indexes should match real access paths; do not add one index
  per filtered column by rote.

## Queries

- SQL is always parameterized. A value never reaches PostgreSQL by concatenation, not for
  a `WHERE`, not for a `LIMIT`, not for an identifier the client chose.
- SQL stays with the package that owns the operation, not in a shared query package.
- `defer rows.Close()` and `defer tx.Rollback()` go next to the acquire.
