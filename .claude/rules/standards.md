# Changing a standard

The files under `.claude/rules/`, `CLAUDE.md`, and `docs/` are the standards the project
owner maintains. They are read before work starts and followed as written.

When a rule blocks a better approach, or a change cannot be made without amending one,
the amendment is proposed first and the work waits for a decision: quote the rule, say
what it prevents, and give the alternative with its tradeoff. Neither the approach nor
the Markdown file is changed until the owner agrees. A rules conflict is a blocking
question, not a judgement call.

Recording what was built needs no such approval: a new endpoint's row in the API
contract, a file table, verification evidence, a page's status in `docs/frontend-pages.md`.
The line is whether the edit changes what the standard requires or only what it records.
